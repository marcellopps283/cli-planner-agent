# Repository Guidelines

## Project Structure & Module Organization

This repository contains a TypeScript CLI called `blueprint`, a planner-agent for generating `.blueprint/` architecture and handoff artifacts.

- `src/`: CLI implementation. Key modules include `cli.ts`, `tui.ts`, `plan.ts`, `profile.ts`, `registry.ts`, `providers.ts`, `lint.ts`, `revise.ts`, and `schemas.ts`.
- `tests/`: Vitest coverage for commands, schemas, registry behavior, TUI rendering, planning, export, and revise flows.
- `docs/`: product decisions, specs, roadmap, ADRs, and operational notes. Read `docs/DESIGN_LOCK.md` and `docs/MVP_ROADMAP.md` before structural changes.
- `.blueprint/`: local generated planning artifacts for this repo. Treat as project state, not source code.
- `dist/`: build output generated by `pnpm build`.

## Build, Test, and Development Commands

- `corepack pnpm install`: install dependencies.
- `corepack pnpm dev -- --help`: run the CLI from source.
- `corepack pnpm typecheck`: run `tsc --noEmit`.
- `corepack pnpm test`: run the Vitest suite.
- `corepack pnpm build`: build `dist/cli.js` with tsup.
- `corepack pnpm check`: run typecheck, tests, and build. Use this before committing.
- `node dist/cli.js providers --models`: smoke-test the built CLI.

## Coding Style & Naming Conventions

Use TypeScript ES modules and keep code explicit over clever. Prefer Zod schemas for external contracts and YAML/JSON parsing through libraries, not ad hoc string handling. File names are lowercase nouns (`registry.ts`, `providerPrompt.ts`); tests use `*.test.ts`. Keep comments sparse and useful. Existing code uses two-space indentation and semicolons.

## Testing Guidelines

Use Vitest. Add focused tests beside the behavior changed: registry changes in `tests/registry.test.ts`, TUI changes in `tests/tui.test.ts`, planner contracts in `tests/plan.test.ts`, etc. Generated `.blueprint/` artifacts must remain lintable. Prefer deterministic tests; live provider calls belong behind explicit smoke commands, not normal tests.

## Commit & Pull Request Guidelines

Follow the current history style: concise imperative commits with a type prefix, for example `feat: refresh project model registry` or `fix: ...`. PRs should describe behavior changes, files touched, validation commands run, and any user-facing CLI/TUI impact. Include screenshots or terminal output for TUI changes when relevant.

## Security & Agent-Specific Instructions

Do not implement cookie/session-token capture. Authentication must use official CLIs (`codex`, `claude`, `gemini`). Do not read or transmit secrets, ignored files, or whole repositories unnecessarily. Structural changes to auth, artifact formats, model routing, or worker execution require an ADR.
